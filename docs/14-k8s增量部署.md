# thing-model 与 UI 增量部署（Kubernetes）

适用场景：服务器上已有 ThingsBoard（Kubernetes 部署），本次追加部署
`thing-model` 服务，并用新的 `ui-ngx` 构建产物替换/新增前端入口。

本方案不修改 ThingsBoard 镜像，只新增：

- `thing-model` Deployment / Service
- `crec-ui` Nginx 静态站点，并代理 `/api` 到 ThingsBoard、`/api/thing-model` 到 thing-model
- Ingress、升级、回滚和排障步骤

## 1. 架构与约定

```text
Browser
  -> Ingress
  -> crec-ui Service (Nginx)
       -> /                  ui-ngx 静态文件
       -> /api/thing-model/  thing-model:8090/api/
       -> /api/              thingsboard:8080/api/
       -> /api/ws            thingsboard:8080/api/ws
       -> /static/           thingsboard:8080/static/
       -> /oauth2/           thingsboard:8080/oauth2/
       -> /login/oauth2/     thingsboard:8080/login/oauth2/
```

以下占位符请按实际环境替换：

| 占位符 | 示例 |
| --- | --- |
| `<namespace>` | `iot-platform` |
| `<registry>` | `registry.example.com/iot` |
| `<tag>` | `1.0.0` |
| `<host>` | `iot.example.com` |
| `<tb-service>` | `thingsboard:8080` |
| `<db-host>` | `postgres:5432` |
| `<kafka-bootstrap>` | `kafka:9092` |
| `<tenantId>` | ThingsBoard 租户 UUID |
| `<db-password>` | thing_model 数据库密码 |
| `<secret-key>` | Base64 编码的 32 字节 AES key |

## 2. 部署前检查

```bash
kubectl version --client
kubectl -n <namespace> get svc
```

确认：

- ThingsBoard Service 名称和端口，例如 `thingsboard:8080`
- PostgreSQL、Kafka 可访问
- 镜像仓库可登录、可推送
- 构建机有 JDK 25、Maven 3.9+、Node 22.22.2、Yarn 1.22.22
- 已准备并妥善保存 `THINGMODEL_SECRET_KEY`

> 重要：`THINGMODEL_SECRET_KEY` 必须固定不变。更换 key 会导致
> `plat_vendor_account` 解密失败，产品同步报 500。

生成 key 的示例：

```bash
openssl rand -base64 32
```

## 3. 构建镜像

在仓库根目录执行。

### 3.1 thing-model

```bash
mvn -f thing-model/pom.xml clean package -DskipTests
```

产物：

```text
thing-model/target/thing-model-0.1.0-SNAPSHOT.jar
```

创建 `Dockerfile.thing-model`：

```dockerfile
FROM eclipse-temurin:25-jre
WORKDIR /app
COPY thing-model/target/thing-model-0.1.0-SNAPSHOT.jar /app/app.jar
EXPOSE 8090
ENTRYPOINT ["java", "-XX:MaxRAMPercentage=75", "-jar", "/app/app.jar"]
```

构建并推送：

```bash
docker build -f Dockerfile.thing-model -t <registry>/thing-model:<tag> .
docker push <registry>/thing-model:<tag>
```

### 3.2 UI

```bash
cd ui-ngx
yarn install --frozen-lockfile
yarn build:prod
cd ..
```

产物：

```text
ui-ngx/target/generated-resources/public/
```

创建 `Dockerfile.crec-ui`：

```dockerfile
FROM nginx:1.27-alpine
COPY ui-ngx/target/generated-resources/public/ /usr/share/nginx/html/
```

构建并推送：

```bash
docker build -f Dockerfile.crec-ui -t <registry>/crec-ui:<tag> .
docker push <registry>/crec-ui:<tag>
```

## 4. 初始化数据库

首次部署时创建 `thingmodel` 数据库和用户：

```bash
kubectl -n <namespace> exec -i deploy/<postgres-deployment> -- \
  psql -U postgres -d postgres \
  -v thing_model_password='<db-password>' \
  < thing-model/deploy/postgres/init-thingmodel.sql
```

也可以直接在 PostgreSQL 中执行 `thing-model/deploy/postgres/init-thingmodel.sql`
的内容。`thing-model` 启动时 Flyway 会自动创建 `plat_*` 表。

如果使用“同库 + 独立 schema”模式，改用：

```text
thing-model/deploy/postgres/init-thingmodel-schema.sql
SPRING_DATASOURCE_URL=jdbc:postgresql://<db-host>/thingsboard
THINGMODEL_DB_NAME=thingsboard
THINGMODEL_DB_SCHEMA=thingmodel
```

## 5. 部署 thing-model

### 5.1 Secret

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: thing-model-secret
  namespace: <namespace>
type: Opaque
stringData:
  SPRING_DATASOURCE_USERNAME: thing_model
  SPRING_DATASOURCE_PASSWORD: "<db-password>"
  THINGMODEL_SECRET_KEY: "<secret-key>"
```

生产环境建议使用 SealedSecret / ExternalSecret / Vault，不要把明文 Secret 提交到 Git。

### 5.2 ConfigMap

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: thing-model-config
  namespace: <namespace>
data:
  SPRING_DATASOURCE_URL: "jdbc:postgresql://<db-host>/thingmodel"
  THINGMODEL_DB_NAME: "thingmodel"
  THINGMODEL_TB_URL: "http://<tb-service>"
  THINGMODEL_KAFKA_BOOTSTRAP: "<kafka-bootstrap>"
  THINGMODEL_TOPIC_TELEMETRY: "iot.telemetry.normalized"
  THINGMODEL_TOPIC_EVENT: "iot.event.normalized"
  THINGMODEL_TOPIC_INVALID: "iot.telemetry.invalid"
  THINGMODEL_KAFKA_KEY_PATTERN: "$[deviceName]"
  THINGMODEL_RULECHAIN_ENABLED: "true"
```

`<tb-service>` 示例：`thingsboard:8080`。

### 5.3 Deployment / Service

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: thing-model
  namespace: <namespace>
spec:
  replicas: 1
  strategy:
    type: Recreate
  selector:
    matchLabels:
      app: thing-model
  template:
    metadata:
      labels:
        app: thing-model
    spec:
      containers:
        - name: thing-model
          image: <registry>/thing-model:<tag>
          imagePullPolicy: IfNotPresent
          ports:
            - containerPort: 8090
          envFrom:
            - configMapRef:
                name: thing-model-config
            - secretRef:
                name: thing-model-secret
          readinessProbe:
            httpGet:
              path: /actuator/health
              port: 8090
            initialDelaySeconds: 20
            periodSeconds: 10
          livenessProbe:
            httpGet:
              path: /actuator/health
              port: 8090
            initialDelaySeconds: 60
            periodSeconds: 20
          resources:
            requests:
              cpu: "200m"
              memory: "512Mi"
            limits:
              cpu: "1"
              memory: "1Gi"
---
apiVersion: v1
kind: Service
metadata:
  name: thing-model
  namespace: <namespace>
spec:
  selector:
    app: thing-model
  ports:
    - name: http
      port: 8090
      targetPort: 8090
```

应用：

```bash
kubectl apply -f thing-model-k8s.yaml
kubectl -n <namespace> rollout status deployment/thing-model
```

> 单副本 + `Recreate` 是为了避免多个实例同时执行 Flyway 迁移。

## 6. 首次注册厂服账号

`thing-model` 需要保存一个 ThingsBoard 厂服账号，用于创建 Device Profile、Asset 和规则链。
首次部署或重置账号时执行一次。

先获取 tenantId 和 sysadmin JWT：

```bash
TENANT_JWT=$(curl -s -X POST "http://<host>/api/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"username":"tenant@thingsboard.org","password":"<tenant-password>"}' | jq -r .token)

TENANT_ID=$(curl -s "http://<host>/api/auth/user" \
  -H "X-Authorization: Bearer $TENANT_JWT" | jq -r .tenantId.id)

SYSADMIN_JWT=$(curl -s -X POST "http://<host>/api/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"username":"sysadmin@thingsboard.org","password":"<sysadmin-password>"}' | jq -r .token)
```

端口转发并注册账号：

```bash
kubectl -n <namespace> port-forward svc/thing-model 8090:8090

curl -X POST "http://localhost:8090/api/admin/tenants/$TENANT_ID/account" \
  -H "X-Authorization: Bearer $SYSADMIN_JWT" \
  -H "Content-Type: application/json" \
  -d '{"username":"tenant@thingsboard.org","password":"<tenant-password>"}'
```

预期返回：

```json
{"tenantId":"...","username":"tenant@thingsboard.org","enabled":true}
```

> 没有这一步，产品同步会报 `TENANT_ACCOUNT_MISSING`。
> 已有服务升级时不要重复注册，除非确认要重置厂服账号。

## 7. 部署 UI 网关

### 7.1 Nginx ConfigMap

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: crec-ui-nginx
  namespace: <namespace>
data:
  default.conf: |
    server {
      listen 80;
      server_name _;
      root /usr/share/nginx/html;
      index index.html;

      client_max_body_size 20m;

      location / {
        try_files $uri $uri/ /index.html;
      }

      location /api/thing-model/ {
        proxy_pass http://thing-model:8090/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
      }

      location /api/ws {
        proxy_pass http://<tb-service>;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
      }

      location /api/ {
        proxy_pass http://<tb-service>;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
      }

      location /static/ {
        proxy_pass http://<tb-service>;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
      }

      location /oauth2/ {
        proxy_pass http://<tb-service>;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
      }

      location /login/oauth2/ {
        proxy_pass http://<tb-service>;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
      }
    }
```

注意：`/api/thing-model/` 的 `proxy_pass` 末尾有 `/api/`，用于把
`/api/thing-model/products` 重写为 `thing-model:8090/api/products`。

### 7.2 Deployment / Service

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: crec-ui
  namespace: <namespace>
spec:
  replicas: 2
  selector:
    matchLabels:
      app: crec-ui
  template:
    metadata:
      labels:
        app: crec-ui
    spec:
      containers:
        - name: crec-ui
          image: <registry>/crec-ui:<tag>
          imagePullPolicy: IfNotPresent
          ports:
            - containerPort: 80
          volumeMounts:
            - name: nginx-config
              mountPath: /etc/nginx/conf.d/default.conf
              subPath: default.conf
          readinessProbe:
            httpGet:
              path: /
              port: 80
            initialDelaySeconds: 5
            periodSeconds: 10
          resources:
            requests:
              cpu: "50m"
              memory: "64Mi"
            limits:
              cpu: "500m"
              memory: "256Mi"
      volumes:
        - name: nginx-config
          configMap:
            name: crec-ui-nginx
---
apiVersion: v1
kind: Service
metadata:
  name: crec-ui
  namespace: <namespace>
spec:
  selector:
    app: crec-ui
  ports:
    - name: http
      port: 80
      targetPort: 80
```

### 7.3 Ingress

如果已有 ThingsBoard 的 Ingress，直接把 `/` 的 backend 改为 `crec-ui`；
也可以新建独立域名。

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: crec-ui
  namespace: <namespace>
  annotations:
    nginx.ingress.kubernetes.io/proxy-body-size: "20m"
    nginx.ingress.kubernetes.io/proxy-read-timeout: "3600"
    nginx.ingress.kubernetes.io/proxy-send-timeout: "3600"
spec:
  ingressClassName: nginx
  tls:
    - hosts:
        - <host>
      secretName: <tls-secret>
  rules:
    - host: <host>
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: crec-ui
                port:
                  number: 80
```

应用：

```bash
kubectl apply -f thing-model-k8s.yaml
kubectl apply -f crec-ui-k8s.yaml
kubectl -n <namespace> rollout status deployment/crec-ui
```

## 8. 产品同步

`thing-model` 部署或升级后，规则链脚本不会自动刷新。需要重新同步产品：

```bash
curl -X POST "http://localhost:8090/api/products/4DZDCQUA2D/sync" \
  -H "X-Authorization: Bearer $TENANT_JWT"
```

也可以通过产品详情页执行同步。同步后会更新：

- Device Profile
- 产品 Asset 属性
- 规则链脚本和绑定关系

## 9. 升级与回滚

### 9.1 升级 thing-model

```bash
kubectl -n <namespace> set image deployment/thing-model \
  thing-model=<registry>/thing-model:<new-tag>
kubectl -n <namespace> rollout status deployment/thing-model
```

升级后重新执行产品同步。升级前建议备份 `thingmodel` 数据库；
Flyway 迁移是向前的，回滚镜像不等于回滚数据库结构。

### 9.2 升级 UI

```bash
kubectl -n <namespace> set image deployment/crec-ui \
  crec-ui=<registry>/crec-ui:<new-tag>
kubectl -n <namespace> rollout status deployment/crec-ui
```

### 9.3 回滚

```bash
kubectl -n <namespace> rollout undo deployment/thing-model
kubectl -n <namespace> rollout undo deployment/crec-ui
```

如数据库迁移导致不兼容，需要恢复升级前的数据库备份。

## 11. 常见问题

### 产品同步 500，日志出现 `Failed to decrypt tenant credential`

`THINGMODEL_SECRET_KEY` 与 `plat_vendor_account` 密文不匹配。

处理：

1. 恢复原来的 `THINGMODEL_SECRET_KEY`，或
2. 重新注册厂服账号（见第 6 节）。

### `/api/thing-model` 返回 404

检查：

- Ingress 是否指向 `crec-ui`
- Nginx 中是否存在 `/api/thing-model/` 路由
- `proxy_pass` 是否为 `http://thing-model:8090/api/`
- `thing-model` Service 是否与 `crec-ui` 在同一命名空间

### 页面刷新 404

`crec-ui` 的 Nginx 缺少 SPA fallback：

```nginx
try_files $uri $uri/ /index.html;
```

### thing-model 启动失败

检查：

- 数据库是否已创建、账号密码是否正确
- `THINGMODEL_TB_URL` 是否指向可达的 ThingsBoard Service
- Kafka 地址是否正确
- Java 镜像是否为 25

### 规则链未更新

修改 `telemetry_to_kafka.js` 后，必须重新同步产品；只重启
`thing-model` 不会更新 ThingsBoard 中已部署的规则链。

### 私有镜像仓库拉取失败

在 Deployment/Pod 模板中配置：

```yaml
imagePullSecrets:
  - name: <registry-pull-secret>
```

## 12. 注意事项

- `THINGMODEL_SECRET_KEY` 必须长期保存，不要随升级变化。
- 本文使用 `stringData` 仅便于演示，生产建议使用 SealedSecret / ExternalSecret。
- 新增 UI 页面依赖 `/api/thing-model` 反代，不能只替换静态文件。
- 升级前备份 `thingmodel` 数据库和当前镜像 tag。
- 已有设备和历史数据不受本次部署影响，但规则链变更需要产品同步后生效。
