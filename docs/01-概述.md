## 1.1  编写背景

中国中铁业务体系内存在大量异构终端，如智能车载终端、智能安全帽、高精度定位接收机、视频监控设备等。这些设备由不同厂商提供，协议、报文格式与数据定义各不相同。过去上层业务系统以“一设备一对接”的烟囱方式建设，造成规范不统一、协议不统一、数据不统一、管理不统一，既拉高了集成成本，也制约了数据资产的沉淀。

2022 年 11 月发布的《中国中铁物联设备接入规范 V1.5》从产品与设备命名、设备三元组与认证、物模型（TSL）、以 `$thing` 为代表的 MQTT 主题体系，以及 JT/T808、HTTPS、CoAP 等接入协议五个层面，统一了设备侧的“契约”。规范同时明确：新增设备以本规范为强制要求，存量设备以经济性为优先，尽量减少拆装与返厂改造。

平台选型结论是**以 ThingsBoard 为底座进行二次开发**。ThingsBoard 原生具备多租户（Tenant / Customer）、设备与资产模型、设备模板（Device Profile）、关系（Relation）、规则引擎、仪表板与开放 API，可以直接承载“产品—设备—物模型—数据”主链路。但需要正视差异：ThingsBoard 的主题体系、认证方式与实体语义均与规范不完全重合，因此必须增加一层**物模型服务**，并把协议差异下沉到**设备侧 SDK**，才能既满足规范的强制性，又保持底座可升级。

## 1.2  建设目标

- **规范语义承载**：设备三元组、TSL 物模型、属性/事件/行为的语义、OTA、远程配置与影子均可按规范落地；MQTT 直连 ThingsBoard 内置 Transport，腾讯 `$thing` 报文由设备侧 SDK 转换后直连。
- **厂商自助接入**：每个硬件厂商一个租户，厂商自行导入物模型、创建产品与设备、上传数据；中铁侧只保留一个超级管理员与统一台账，不替厂商管设备。
- **物模型驱动**：TSL 是唯一事实来源，设备模板、校验规则、事件约定、开放接口的数据字典均由 TSL 自动生成，避免多套定义漂移。
- **可演进的二次开发框架**：不修改 ThingsBoard 核心表结构与内核代码，扩展以独立服务、规则链节点、REST 集成与前端插件的方式实现，保证底座版本可平滑升级。
- **面向业务开放**：为业务中台、大屏、移动端提供统一的设备查询、指令下发、事件订阅接口。
- **与腾讯 IoT 对齐**：产品、设备、物模型与数据契约和腾讯云 IoT Hub 保持一致；存量设备升级固件后直连，平台侧不部署外部 Broker。

## 1.3  设计依据

- 《中国中铁物联设备接入规范 V1.5》（2022 年 11 月），以下简称“规范”。
- 腾讯云 IoT Hub / 物联网开发平台文档：产品、设备、物模型、Topic 与设备影子等章节（作为规范的同源参考）。
- ThingsBoard PE 官方文档：Digital Twin Model（数字孪生模型）、Multi-Tenancy & Hierarchy、Data Processing、MQTT API、REST API 等章节。
- 工作区内样例物模型 `9HYN9PJNOY.json`（WiFi 诊断类终端，33 个只读属性），用于验证 TSL → 设备模板的转换规则。

## 1.4  术语与概念对齐

规范与 ThingsBoard 使用了两套术语。为避免设计与实现中的歧义，先建立如下对照关系，后续章节均按此口径表述。

**表 1-1  规范概念与 ThingsBoard 实体映射**

| 规范概念 | 规范中的定义要点 | ThingsBoard 对应实体 | 落地说明 |
| --- | --- | --- | --- |
| 物模型（TSL） | 设备在平台端的数字抽象，由属性、事件、行为构成，JSON 描述 | Device Profile + 平台侧 TSL 注册表 | TSL 原文由物模型服务保存，Profile 为生成物 |
| 属性 | 设备到平台的数据流，描述实时状态；支持 7 种数据类型，分只读（r）与读写（rw） | Telemetry（遥测） | 上行一律遥测；rw 的下行走 RPC |
| 事件 | 设备到平台，分信息（info）、告警（alert）、故障（fault），可带多个输出参数 | Telemetry（保留键） | 三类事件都随遥测上报，平台落事件表 |
| 行为 | 平台到设备的调用，含输入/输出参数，用于执行复杂业务逻辑 | RPC（双向 RPC） | actionId → RPC 方法名，params → RPC 参数 |
| 产品（ProductID） | 同一类设备的集合，平台颁发全局唯一 ProductID | Device Profile | 一个产品对应一个设备模板，ProductID 作为模板元数据 |
| 设备（DeviceName） | 产品实例，产品内唯一，命名规则为“设备型号+序列号” | Device | Device.name 直接使用 DeviceName，label 存中文别名 |
| 设备三元组 | ProductID + DeviceName + DeviceSecret/证书，用于鉴权 | Device 凭证（Access Token / X.509 / MQTT Basic） | 密钥→TB 凭证；HMAC 签名随固件升级废弃 |
| 设备影子 | 缓存设备最新状态，供应用读写 | 少量 Attributes + 最新遥测 | 期望值用共享属性，实况用遥测 |
| 远程配置 | 平台向设备下发系统参数 | Shared Attributes | 以 `cfg_json` 共享属性承载 |
